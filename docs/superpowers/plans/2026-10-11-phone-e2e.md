# Phone E2E — real payments, against the app as it is now

> **Replaces Task 12 of `2026-07-03-phase1a-capture-core.md`.** That script predates 1B–4B and the
> gate redesign: it taps a button that no longer exists ("Nope, saved"), expects amounts the app no
> longer renders ("₹0.00"), looks for the budget and the rows on Home (both are on the Dashboard),
> and tests nothing built since July. Every label, amount and count below was checked against the
> code at `e649bbd` on 2026-10-11.

**What it proves.** The scan → gate → UPI → confirm → garden loop with real money on a real phone,
through all three gate cards — plus the two things only a real payment can show: whether a shop's QR
pays cleanly through the app's *rebuilt* intent (see Step 9), and whether the weed the gate previews
is the weed that grows.

**Cost:** ₹3 — three ₹1 payments. Every other budget state is set up with free manual entries.

**Time:** about 40 minutes. **Do it in one sitting, on or before the 26th** (the 25th in a 30-day
month). Each step's numbers depend on the month total the step before left behind, and Step 3's
pace card can't fire later in the month.

**It ends by wiping the app's data** (Step 10). The run leaves ~₹1,000 of fake spending in the
ledger; the wipe is what lets your real ledger start clean.

## What you need

- The phone with **USB debugging** on (Settings → About phone → tap *Build number* 7 times →
  Developer options → USB debugging), and a cable.
- A UPI app with at least ₹3 behind it. **Use the same app for all three payments**, so the
  shop-versus-person comparison isn't muddied by switching apps.
- **A shop's UPI QR** you can pay ₹1 to. A PhonePe / Paytm / Google Pay sticker is ideal.
  **Not your own QR** — paying your own VPA from the same account will most likely be refused
  (payer and payee are the same), and that failure would say nothing about this app.
- **A family member's personal QR** (their UPI app's "receive money" screen), for the
  person-to-person comparison.
- The Mac, at the repo root.

## Read this first

- **Use the gate's buttons; never tap outside the dialog.** Tapping outside only closes it: nothing
  is recorded and you stay on the entry screen.
- **Don't enter the Gemini key in Settings yet.** Without one the gate draws from the 5 static
  quips per severity, which keeps Step 7's rotation check deterministic.
- **When you tap a plant to inspect it, leave with "Close".** "Worth it" and "Regret" write to the
  ledger.
- **If a payment fails:** **Discard** the "Did ₹1 to ‹shop name› go through?" card, write down the
  exact error, and carry on. "If something goes wrong" at the bottom says how to keep the numbers
  right.

## Step 0 — Connect, run the instrumented suite, install

1. Plug the phone in, unlock it, and run:

   ```bash
   ~/Library/Android/sdk/platform-tools/adb devices
   ```

   Expected: a line `<serial>	device`. If it says `unauthorized`, accept *Allow USB debugging?* on
   the phone (tick *Always allow*) and run it again. `<serial>` below means that value.

2. Make sure nothing you care about is installed already — the next command uninstalls the app:

   ```bash
   ~/Library/Android/sdk/platform-tools/adb -s <serial> shell pm list packages com.expensegarden.app
   ```

   Expected: no output. If it prints `package:com.expensegarden.app` and that install holds real
   data, stop here.

3. Run the 92 instrumented tests on the phone. This covers what the 2026-10-11 JVM run couldn't:
   `RareDeterminismTest` lives in `androidTest`, and it is the test that used to fail from the 8th
   of the month.

   ```bash
   JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home ANDROID_SERIAL=<serial> ./gradlew connectedDebugAndroidTest
   ```

   Expected: `BUILD SUCCESSFUL`. Then count what actually ran, because a run of zero tests says
   BUILD SUCCESSFUL too:

   ```bash
   python3 -c "import glob,os,xml.etree.ElementTree as E; f=max(glob.glob('app/build/outputs/androidTest-results/connected/debug/*.xml'),key=os.path.getmtime); r=E.parse(f).getroot(); print(os.path.basename(f), 'tests', r.get('tests'), 'failures', r.get('failures'), 'errors', r.get('errors'), r.get('timestamp'))"
   ```

   Expected: your phone's name in the file name, `tests 92 failures 0 errors 0`, and today's date.
   The task uninstalls the app when it finishes — harmless today, destructive once the phone holds
   a real ledger. CLAUDE.md has the details.

4. Install:

   ```bash
   JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home ANDROID_SERIAL=<serial> ./gradlew installDebug
   ```

   Expected: `Installed on 1 device.`

5. Open **Expense Garden**. Expected: the island with no plants; the strip at the top reads **₹0**
   on the left and **set a budget  ›** on the right; **Scan & pay** and **Log manually** at the
   bottom.

## Step 1 — A ₹1,000 budget (free)

Tap the strip → **This month** → **Set overall budget** → *Amount (₹)* `1000` → **Save**.

Expected: the button now reads **Budget: ₹1,000**. Tap **← garden**: the strip reads **₹0** and
**₹1,000 · on pace  ›**.

## Step 2 — Shop QR, no gate, ₹1 real · plus a kill mid-flow

1. **Scan & pay** → allow the camera the first time → scan the **shop's** QR.
   Expected: **Paying ‹shop name›**, with the amount field focused and empty.
2. Amount `1` → **Shopping** (it's one of the chips) → **Continue to pay**.
   Expected: **no gate** — ₹1 can't cross the pace line on any day of the month — then **Pay with**
   (or your UPI app directly, if it's the only one).
3. In the UPI app, note what it shows (payee name, any *verified* badge, whether ₹1 came
   pre-filled), then pay ₹1.
4. Back in Expense Garden. Expected: a card **Did ₹1 to ‹shop name› go through?**, today's date and
   the time under it, and **Log it** / **Discard**.
5. **Don't tap it yet.** Kill the app from the Mac, then reopen it on the phone:

   ```bash
   ~/Library/Android/sdk/platform-tools/adb -s <serial> shell am force-stop com.expensegarden.app
   ```

   Expected: **Did ₹1 to ‹shop name› go through?** is still there — a pending payment survives the
   process dying.
6. **Log it.** Expected: strip **₹1** · **₹1,000 · on pace**, one plant on the island, and a bar at
   the bottom: **Logged ₹1 to ‹shop name›** with **Undo**. Don't tap Undo — the bar goes by itself
   after 10 seconds, and every **Log it** and **Discard** from here on shows one like it. Tap the
   plant: **₹1 — ‹shop name›** and **Shopping · ‹today›** → **Close**.

## Step 3 — Ahead of pace: the streak card (free)

1. **Log manually** → *Amount* `990` → *Paid to* `E2E setup` → **Shopping** → **Log it**.
   Expected: no dialog (manual entries are never gated); strip **₹991** · **₹1,000 · ahead of
   pace**.
2. **Scan & pay** → the shop QR. Expected: **Shopping is already selected** — payee memory from
   Step 2.
3. Amount `1` → **Continue to pay**. Expected, the streak card:
   - **This puts you further ahead of pace** — Step 3.1 already put you ahead, so this ₹1 ends no
     streak, and the card doesn't claim one
   - a quip
   - **₹584 over today's ₹408** on the 11th. On another day the two figures move, but in whole
     rupees they always add up to the month's total after this payment, **₹992**, give or take ₹1
     of rounding.
   - a filled **Not now**, with **Pay anyway** as plain text below it
4. **Not now.** Expected: back on the island, strip still **₹991**. That's dodge 1 of 3.

## Step 4 — Over budget: the weed card, ₹1 real, and the weed it promised

1. **Log manually** whatever takes the month to exactly **₹1,000** — `9` if Step 2's payment went
   through — *Paid to* `E2E setup`, **Shopping**, **Log it**.
   Expected: strip **₹1,000** · **₹1,000 · ahead of pace**. ₹1,000 is not *over* ₹1,000, so this
   entry grows an ordinary plant, not a weed.
2. **Scan & pay** → the shop QR → amount `1` (Shopping pre-selected) → **Continue to pay**.
   Expected, the weed card:
   - a sprite — a **thistle** or a **mushroom**. **Write down which.**
   - **This grows a weed**
   - a quip
   - **₹1 over**
   - **Not now** filled, **Pay anyway** as text
3. **Pay anyway** → pay ₹1 (note what the UPI app shows) → back in the app, **Log it**.
   Expected: strip **₹1,001** · **₹1,000 · over budget**, and **the weed you wrote down** grows on
   the island. Tap it: **₹1 — ‹shop name›**, **Shopping · ‹today›** → **Close**.

   This is the preview checked end to end. Which weed grows is a pure function of the transaction's
   id, and the app now mints that id at scan time so the card can show it. Every scan mints a new
   id, so a later scan may well preview the other weed — expected, not a bug.

## Step 5 — A necessity: the neutral card (free)

1. **Scan & pay** → the shop QR → amount `1` → switch the category to **Groceries** →
   **Continue to pay**. Expected, the neutral card, left-aligned:
   - **Overall, after this**
   - **₹1,002 of your ₹1,000 budget.**
   - **Nothing grows badly here — necessities never do.**
   - **no quip and no sprite**
   - **Back** as text and **Continue** filled, both on the right
2. **Back.** Expected: back on the island, nothing logged. This must **not** count as a dodge;
   Step 7 checks that from the phone.

## Step 6 — A person's QR: a necessity that pays, ₹1 real

1. **Scan & pay** → the **family member's** QR → amount `1` → **All…** → **Family** →
   **Continue to pay**. Expected: the neutral card again, **₹1,002 of your ₹1,000 budget.**
2. **Continue** → pay ₹1 (note what the UPI app shows) → **Log it**.
   Expected: strip **₹1,002**, and a new plant that is **not** a thistle or a mushroom — a
   necessity never grows a weed, even over budget. Tap it: **₹1 — ‹their name›**,
   **Family · ‹today›** → **Close**.

## Step 7 — Quip rotation, and the rare for backing out (free)

Three back-outs in a month earn a rare (`RareEngine.DODGES_FOR_EARN = 3`). It is banked rather
than planted, so it shows up on the greenhouse's Collection card as a "waiting" line. *When* that
line appears is the check that Step 5's **Back** didn't count.

1. **🏡 greenhouse.** Expected: **Collection** reads **0 of 16**, with **no "waiting" line**.
   **← garden**.
2. **Scan & pay** → the shop QR → amount `1` (Shopping pre-selected) → **Continue to pay**.
   Expected: the weed card, with a **different quip** from Step 4's. **Not now** — dodge 2.
3. **🏡 greenhouse.** Expected: **still no "waiting" line.** If Step 5's **Back** had counted, that
   was the third back-out and the line would already be here.
4. Repeat 7.2: a **third different quip** → **Not now**. Dodge 3.
5. **🏡 greenhouse.** Expected: **1 waiting — your next purchase will grow one.**

## Step 8 — Read the ledger (on the Mac)

Retail phones usually don't ship `sqlite3`, so pull the database and query it here. Room keeps it in WAL
mode, so recent writes may still sit in `garden.db-wal` — pull both files.

```bash
~/Library/Android/sdk/platform-tools/adb -s <serial> shell am force-stop com.expensegarden.app
```

```bash
~/Library/Android/sdk/platform-tools/adb -s <serial> shell run-as com.expensegarden.app ls databases
```

Expected: `garden.db`, `garden.db-shm`, `garden.db-wal`. (No `-wal` listed? Skip that pull below.)

```bash
mkdir -p /tmp/garden-e2e
```

```bash
~/Library/Android/sdk/platform-tools/adb -s <serial> exec-out run-as com.expensegarden.app cat databases/garden.db > /tmp/garden-e2e/garden.db
```

```bash
~/Library/Android/sdk/platform-tools/adb -s <serial> exec-out run-as com.expensegarden.app cat databases/garden.db-wal > /tmp/garden-e2e/garden.db-wal
```

```bash
sqlite3 /tmp/garden-e2e/garden.db "SELECT type, COUNT(*) FROM game_event GROUP BY type ORDER BY type;"
```

Expected, if all three payments went through:

```
budget.breached|1
budget.pace_warning|1
budget.set|1
gate.dodged|3
transaction.logged|5
```

`gate.dodged|3` is Steps 3, 7.2 and 7.4, and not Step 5. `budget.set|1` is Step 1's ₹1,000; the
other two `budget.*` rows mark the moments the month crossed the pace line (Step 3's ₹990) and the
budget (Step 4's ₹1).

```bash
sqlite3 -header -column /tmp/garden-e2e/garden.db "SELECT t.amountPaise/100.0 AS rupees, t.source, t.status, t.breachedAtLogging AS breached, c.name AS category FROM txn t JOIN category c ON c.id = t.categoryId ORDER BY t.createdAt;"
```

Expected, in this order:

| rupees | source | status | breached | category |
|---|---|---|---|---|
| 1.0 | QR_GATE | LOGGED | 0 | Shopping |
| 990.0 | MANUAL | LOGGED | 0 | Shopping |
| 9.0 | MANUAL | LOGGED | 0 | Shopping |
| 1.0 | QR_GATE | LOGGED | **1** | Shopping |
| 1.0 | QR_GATE | LOGGED | 0 | Family |

Only the fourth row has `breached = 1`. The Family payment was over budget too; it is `0` because a
necessity's card logs as a pace warning, never a breach. A payment you discarded shows up as an
extra `DISCARDED` row and is missing from `transaction.logged`.

## Step 9 — Write down what happened

| | Step 2 — shop | Step 4 — shop | Step 6 — person |
|---|---|---|---|
| UPI app | | | |
| Payee name it showed | | | |
| *Verified* / merchant badge? | | | |
| ₹1 pre-filled? | | | |
| Result — success, or the exact error | | | |
| Anything odd | | | |

Also note: the Step 0 test count, any step whose Expected didn't match (the step number and what you
saw instead).

**Reading the results.** The app doesn't hand the UPI app the QR you scanned. `UpiIntents` builds a
fresh `upi://pay` from five of its fields (`pa`, `pn`, `am`, `cu`, `tn`) and drops the rest —
including `mc` (merchant category), `tr` (transaction reference), `mode`, `orgid` and `purpose`. No
spec or plan records that as a decision, and `UpiIntents` has no tests.

- **All three paid:** the rebuilt intent works with your UPI app for both kinds of QR. Record that
  against "UPI intent quirks" in the parent spec's risk table (§14) and move on.
- **The shop failed or warned and the person didn't:** the dropped merchant fields are the prime
  suspect. Retry the shop in a second UPI app if you have one, and get the shop QR's raw text
  (Google Lens on the QR → copy). That text is the input for a test-first fix that passes the
  original fields through and overrides only the amount. The fix needs a short design first: a
  signed dynamic QR carries a `sign` that an edited amount would invalidate.
- **Everything failed:** not a merchant-fields problem. Bring the exact error and the app's name.

## Step 10 — Wipe the test data (the last time it's safe)

```bash
~/Library/Android/sdk/platform-tools/adb -s <serial> shell pm clear com.expensegarden.app
```

Expected: `Success`. Then put the daily build on. The release build isn't debuggable, which makes
the garden draw several times faster, and it's signed with the same key, so it updates the app in
place:

```bash
JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home ANDROID_SERIAL=<serial> ./gradlew installRelease
```

Expected: `Installed on 1 device.` Step 8's `run-as` pull no longer works on this build; that is
what not debuggable means. Reopen: **₹0**, **set a budget  ›**, the island with no plants. Now set
your real budget, and re-log the ₹3 by hand if you want it counted.

From this point the phone holds your real ledger. **Don't run `connectedDebugAndroidTest` with it
plugged in** — CLAUDE.md has why.

## If something goes wrong

- **"Not a UPI QR".** The code isn't a `upi://pay` link — most likely a Bharat QR (EMVCo format,
  common on bank-issued stickers), which the parser doesn't read. Note it, because that's a real gap
  for daily use, and use another shop's QR.
- **"No UPI app found".** Nothing on the phone handles `upi://`. Install a UPI app, then
  **Discard** the pending card it left behind.
- **A gate in Step 2.** Check the strip: ₹0 spent and a ₹1,000 budget. ₹1 can't cross the pace
  line on any day of the month.
- **No gate in Step 3.** Either it's past the 26th (25th in a 30-day month), or the ₹990 landed in
  another month — the manual entry's **On ‹date›** button should show today.
- **A payment failed.** Discard it, note the error, keep going, and adjust:
  - Step 4's top-up is whatever takes the strip to exactly ₹1,000.
  - The neutral card's figure is the strip's total plus ₹1, not necessarily ₹1,002.
  - Step 8 shows one fewer `transaction.logged`, and one `DISCARDED` row, per failed payment.
  - If Step 4's own payment fails, redo Step 4 with the family member's QR — the weed check only
    needs one success.
